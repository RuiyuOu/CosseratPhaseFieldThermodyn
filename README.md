# Cosserat–KWC plate impact (FreeFem++)

Dynamic finite-deformation plane-strain Cosserat crystal plasticity with the KWC orientation phase field, on an 8-grain
[1-10] Rice planar-triple-slip polycrystal loaded by a moving plate. Units: µm, ns, GPa, K.

## Production model (v2, since 15 November 2026)

`OLD=1` (or `INERTIA=1`) is the same solver with rotational inertia j = 0.01, θ integrated by Newmark; nothing else differs (section "The `OLD=1` set-up" below).

- **Kinematics:** F = R(θ) Ū F_p, F_p updated by the exact exponential of the slip (3 systems) and grain-boundary spin increments.
- **Elasticity:** Vinet volumetric law and isochoric cubic Green-strain energy, integrated at the 3 edge midpoints of each P2 triangle.
- **Cosserat coupling:** the constraint a = 0 (a = skew part of Ū), enforced exactly in every element (Gauss mean) by one multiplier λ per element, ψ += λ a + 2μ_c a² with the augmentation μ_c = 754 GPa.
- **Lattice rotation:** no rotational inertia (j = 0): θ follows a quasi-static (elliptic) balance at every instant.
- **KWC:** ψ = f₀[(1−φ)²/2 + a²|∇φ|²/2 + s g(φ) N(∇θ)], with g = −2[φ + ln(1−φ)] and N = √(|∇θ|² + δ²) − δ, δ = 5e-4.
- **Plasticity:**
  - thermal activation in series with relativistic drag;
  - mobile density ρ_M evolved, with drag density min(ρ_M, ρ_S + ρ_G);
  - GND density from the planar Cermelli–Gurtin tensor, ρ_G = |c/J_p|/b with c_i = ∂₁F_p,i2 − ∂₂F_p,i1 (no reference subtraction);
  - sweeping recovery (Ask et al. 2019), with storage capped by the dissipation.
- **Loading:** left edge clamped; the right edge is the plate (ramp 0.5 ns, hold 2 ns); top and bottom free. A plate speed V at ANGLE splits into compression V cos(ANGLE) along −x and shear V sin(ANGLE) along +y.
- **Numerics:**
  - Newmark average acceleration;
  - Newton on (U, λ) together, with the exact Gauss-point tangent and a line search; the derivatives of the element map (stresses and
    resolved stresses with respect to F, θ, the slip/spin increments and λ) come from forward-mode automatic differentiation in the
    plugin `plugin/kwc2d.cpp`; the KWC term uses the exact reduced Newton tangent of the primal–dual (Chan–Golub–Mulet) system, unsymmetrised (`-kwctan 3`);
  - the tangent matrix and every matrix and vector of the staggered fields assembled directly by the plugin on fixed sparsity
    patterns, compared with the FreeFEM forms every 50th call;
  - MPI: FGMRES on the (U, λ) system with a Schur-complement preconditioner (ASM/ILU on the (u, θ) block), MUMPS fallback;
  - backward-Euler local slip and spin update;
  - staggered phase-field solve: primal–dual active set, each iteration solved by projected CG (CG + Jacobi on the free nodes;
    Gould, Hribar and Nocedal 2001); heat solve.
- **Start:** 100 zero-load relaxation steps (φ starts at 0.999), then the load. DT 0.01 ns, t_end 30 ns.

Parameter values are the defaults in the options table below.

## Production freeze (version 8.0)

The solver is frozen at the kt3pcg set-up. Frozen files (sha256 in `SOLVER_SHA256`): `cosserat_kwc.edp`, `v2/make_v2.py`,
`mpi/make_mpi.py`, `plugin/kwc2d.cpp`, `plugin/dual.hpp`, the generated `cosserat_kwc_v2.edp` and `cosserat_kwc_v2_mpi.edp`, and `tag.sh`
(the parameters). `bash checks/verify_solver.sh` checks them, and every start of `run.sh` writes `solver frozen` or `solver MODIFIED` into
the run's `.out` file.

- **Production run:** no physics variables. `ANGLE=90 ARRAY=3-5 bash submit_speeds.sh` gives the tags `a90_up150ms_v2` … `a90_up400ms_v2`.
  The kt3pcg folders (`RUNTAG=kt3pcg KWCTAN=3`) have the same physics under their own tag; keep using `RUNTAG=kt3pcg` for them.
- **What still changes:** post-processing (`post/`, its own log in `post/CHANGELOG.md`), the documentation, and the submit and helper
  scripts. None of these can change a solution.
- **Not production:** `remesh/` and `remeshtest/` are the mesh-convergence studies; they hold their own solver copies from earlier
  versions. `tools/` holds the KWC-parameter fit and the debug-build generator (`tools/README.md`).

## Installation

FreeFEM 4.15 with PETSc, as a module: `cluster/README.md` (Longleaf and Sycamore; `module use $HOME/modulefiles && module load freefem/4.15`).
The solver also needs its plugin `kwc2d.so`; `run.sh` and the submit scripts build it with `ff-c++` from that module
(`plugin/build_plugin.sh`; nothing to do by hand).

## Running on Longleaf

```bash
bash setup_py.sh                                   # once, on a login node: post-processing venv ($HOME/dynpost_venv)
bash submit_ladder.sh                              # angles 0 45 90 x speeds 25 50 100 150 250 400 m/s (16 ranks, 48 GB per run)
ANGLE=0 bash submit_speeds.sh                      # one angle, all speeds
ARRAY=5 ANGLE=90 bash submit_speeds.sh             # one angle, one speed (5 = 400 m/s)
RUNTAG=s12 KWCS=1.2 bash submit_ladder.sh          # changed parameters need a new RUNTAG
ANGLE=45 bash resume.sh                            # resubmit after crashes
squeue -u $USER;  tail -qn 1 out_a*_up*ms_v2/*_log.csv # queue and progress (column 2 = time in ns)
```

- Every script runs the MPI solver unless `MODE=serial` is set, for example `MODE=serial ANGLE=0 bash submit_speeds.sh`. Serial runs use 1 core, DT 0.005 ns and the tag suffix `_serial`.
- The submit scripts queue the relaxation job first. It makes `relax_checkpoint_v2.txt` (`OLD=1`: `relax_checkpoint_j.txt`) if it is missing and does nothing if the file exists with the same parameters; every run starts from it.
- Rerunning a submit script resumes unfinished runs and skips finished ones. Each 24 h array link continues from the last checkpoint, and links of finished runs exit at once.
- The production solver `cosserat_kwc_v2.edp` is generated from the base solver `cosserat_kwc.edp` by `v2/make_v2.py`, and the MPI versions `cosserat_kwc_v2_mpi.edp` and `cosserat_kwc_mpi.edp` by `mpi/make_mpi.py`. Never edit a generated file: `plugin/build_plugin.sh` (called by the submit scripts and `run.sh`) regenerates them whenever a source is newer. Edits go into `cosserat_kwc.edp` (the shared source) or `v2/make_v2.py` (the v2 patches); both set-ups run the v2 files.
- Every start of `run.sh` writes a `HOST` line to `out_<tag>/<tag>.out`: node, CPU model, the CPUs Slurm gave the job and how many physical cores they are, node load. `grep HOST out_*/*.out` shows which hardware each run got (Longleaf nodes differ).
- Settings files written before the AD change still contain `-fdk`/`-fdq`; `run.sh` ignores those two when it compares settings, so old run folders resume and an old `relax_checkpoint.txt` stays valid.

## Mesh and grain angles

`mesh.msh` and `grain_angles_*.txt` are made from a Neper tessellation, whose files are kept in `mesh/`:

```bash
# 1. tessellation (Neper, built from github.com/neperfepx/neper): 8 grains in a 10 x 10 um square, seed 1
neper -T -n 8 -dim 2 -id 1 -reg 1 -domain "square(10,10)" -oridescriptor euler-bunge -format tess,geo,ori -o MPTD_2D
# 2. FreeFem mesh and grain angles
python3 mesh/make_mesh.py mesh/MPTD_2D.geo mesh/MPTD_2D.ori --out mesh_build
cd mesh_build && FreeFem++ -nw make_mesh.edp && cd ..
cp mesh_build/mesh.msh mesh_build/grain_angles_deg.txt mesh_build/grain_angles_rad.txt .
```

- **Mesh:** FreeFem `buildmesh` with one straight border per line of `MPTD_2D.geo`. Grain boundaries get segments of about 0.05 µm and boundary label 100 + line number; the outer sides get about 0.1 µm segments and labels 1 (left), 2 (bottom), 3 (right), 4 (top). Each triangle's region is its grain number, the `.geo` surface number, which is also the row of `MPTD_2D.ori`.
- **Grain angles:** θ = Euler–Bunge φ₁ reduced modulo 180° into [−180°, 0). With [1̄10] out of plane the lattice repeats every 180°.
- **Check:** these steps reproduce the repository's `mesh.msh` (29,399 vertices, 58,391 triangles, 1,227 boundary edges; same triangles and labels, vertices within 5×10⁻⁷ µm) and its angle files exactly.

## Checks

`bash checks/run_tangent_check.sh` (serial, needs `relax_checkpoint.txt`) checks against central differences: the AD element-map
derivatives on every element (`-adcheck`; expected |FD − AD| ≈ 1e-7 of the largest entry, the FD error, and plugin vs solver values ≈ 1e-13),
the assembled tangent (`-tancheck`; ≈ 1e-7, falling as h² to ≈ 1e-8) and the driving forces and internal force against energy derivatives
(`-check`). Run it after any change to the element map, in the solver or in `plugin/kwc2d.cpp`. `checks/probe_mpi.edp` and
`checks/probe_mumps.edp` test a FreeFem module's MPI/PETSc and MUMPS. `bash checks/verify_solver.sh` checks the frozen solver files
against `SOLVER_SHA256`. `checks/phase_solver/` holds the benchmark scripts behind the phase-solver comparison (production notes, 6.13).

## The `OLD=1` set-up

`OLD=1` (or `INERTIA=1`) in front of any script runs the same v2 solver with every setting of the default (Cosserat multiplier with
μ_c = 754, δ = 5e-4, numerics, tolerances, safeguards) except the micro-inertia j = 0.01 µm², so θ is integrated by Newmark like u.
Tag suffix `_j`, relaxation checkpoint `relax_checkpoint_j.txt`. Folders ending in `_old` (the former `OLD=1` with the Cosserat penalty),
without a suffix (the base solver before 15 November 2026) and those of the former `EXP=1` trials (`out_*_exp`) are not resumed. Differences and checks:
`cosserat_kwc_production.md`, Section 15, and `v2/README.md`.

`VERBOSE=1` prints two timing lines per step in the `.out` file. Hardware (all scripts): `--hint=nomultithread`, a check that every
rank has a physical core (exit 3 otherwise), and `HWCONSTRAINT`, `HWEXCLUDE`, `HWEXCL=1` on the submit scripts; `bash hw.sh` lists the
node types (`v2/README.md`, section Hardware).

```bash
HWCONSTRAINT='amd&avx512' ARRAY=3-5 UPS="150 250 400" bash submit_ladder.sh      # v2: angles 0 45 90 x 150, 250, 400 m/s
OLD=1 ARRAY=3-5 UPS="150 250 400" bash submit_ladder.sh                          # the same ladder with rotational inertia
```
