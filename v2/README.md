# Production set-up v2 (default since 15 November 2026)

Every script runs the v2 solver (`cosserat_kwc_v2.edp`, `cosserat_kwc_v2_mpi.edp`; generated by `v2/make_v2.py`, then
`mpi/make_mpi.py`; `plugin/build_plugin.sh` does both). It has two set-ups, which differ only in the rotation physics. The full model
and numerics are in `cosserat_kwc_production.md`; this file is the operational summary.

| | default | `OLD=1` (or `INERTIA=1`) |
|---|---|---|
| run folder | `out_a<angle>_up<speed>ms_v2[_<RUNTAG>]` | `out_a<angle>_up<speed>ms_j[_<RUNTAG>]` |
| relaxation checkpoint | `relax_checkpoint_v2[_<RUNTAG>].txt` | `relax_checkpoint_j[_<RUNTAG>].txt` |
| micro-inertia `J` | **0** (θ quasi-static) | 0.01 µm² (θ by Newmark, like u) |

The same in both: the Cosserat **multiplier** per element (constraint ā_e = 0, `MUC` **754** GPa the augmentation, `-almc 4`), its merit and
convergence test, the FGMRES/Schur linear solve and `.mult` side file; δ (`KWCD`) 5e-4; the primal–dual KWC tangent; the direct assembly
(`FASTASM`, default 1); the exact slip law; the local acceptance test (`LOCALTOL`, 1e-10); the rotation-branch guard (`BETAMAX`, π/4 rad);
grain-boundary spin `ETASTAR` 1 GPa·ns; phase field `ETAPHI QPHI ETAPHIMIN` 0.1, 100e3, 1e-2; every other parameter and safeguard.
The option lists of the two set-ups differ only in `-j`.

`J`, `KWCD` and `MUC` are still set by their environment variables; a run with other values needs its own `RUNTAG` (the relaxation
checkpoint then gets the same tag). With the multiplier `MUC` must be > 0.

Earlier meanings of `OLD=1`, kept as archives and not resumed: the v2 solver with the Cosserat penalty (μ_c 75.4; folders `_old`,
`relax_checkpoint_old.txt`, until the evening of 15 November 2026) and the base solver `cosserat_kwc.edp` (δ = 0.005, exact KWC Hessian,
form assembly, capped slip law; folders without a suffix, `relax_checkpoint.txt`).

`EXP=1` is accepted and ignored with a note (the former experimental set-up is the default now). Folders of the `EXP=1` trials
(`out_*_exp`, `relax_checkpoint_exp.txt`) were run with η* = 0.1 or 0.02 and an older solver file; neither set-up resumes them.

## Run

```bash
HWCONSTRAINT='amd&avx512' ARRAY=3-5 UPS="150 250 400" bash submit_ladder.sh   # angles 0 45 90 x 150, 250, 400 m/s, 16 ranks each
tail -qn 1 out_a*_up*ms_v2/*_log.csv | cut -d, -f1-4                          # progress: step, time, load, iterations
tail -n 3 out_a0_up400ms_v2/a0_up400ms_v2_newton.csv                          # per step: iterations, wall seconds, max |abar|, max |beta| (deg)
grep -h "fallbacks" out_a*_up*ms_v2/*.out                                     # MUMPS fallbacks of the Krylov solve (end of a run)
VERBOSE=1 ... bash submit_ladder.sh                                           # two timing lines per step in the .out file
ASMCHECK=50 ... bash submit_ladder.sh                                         # every 50th Newton iteration: direct assembly vs forms, entry by entry
grep -h "ASMCHECK:" out_a*_up*ms_v2/*.out                                     # number of comparisons and the largest deviation (end of a run)
OLD=1 ANGLE=45 bash resume.sh                                                 # continue a run of the OLD=1 set-up
grep -h "branch guard" out_a*_up*ms_*/*.out                                   # largest accepted |beta| and rejections (end of a run)
```

`VERBOSE=1` prints, per step and on rank 0 (CPU seconds): the Newton parts (local update, tangent [element, assembly, matrix
hand-over], residual, linear solve) and the whole step (before Newton + Newton, of it the line search, + after Newton: phase field,
temperature, densities, output, checkpoints).

## Hardware

Both `.sbatch` files ask for `--hint=nomultithread` (one rank per physical core). The node can still hand out hyperthread siblings, so
`run.sh` counts the physical cores of the CPUs the job got (the `HOST` line of the `.out` file) and stops with exit code 3 if there are
fewer than ranks; `HWGUARD=0` runs anyway. To choose the hardware:

```bash
bash hw.sh                          # node types of the partition: nodes, nodes with free CPUs, CPUs, memory, features
bash hw.sh model <feature>          # CPU model of such a node
bash hw.sh test <feature>           # estimated start of a 16-rank job on them (nothing is submitted)
HWCONSTRAINT=<feature> ARRAY=3-5 UPS="150 250 400" bash submit_ladder.sh
```

`HWEXCL=1` takes the whole node (all of its memory bandwidth), `HWEXCLUDE=<node,...>` avoids nodes. On Longleaf `amd&avx512` selects
the EPYC 9654 nodes (384 CPUs, 2 threads per core).

## Solver-level options

Set by `run.sh`/`tag.sh`; not meant to be changed for production runs.

| Option | v2 | Meaning |
|---|---|---|
| `-kwctan 0\|2\|3` | 3 (`KWCTAN`, since 8.0) | KWC tangent: exact Hessian of the primal problem / primal–dual, symmetrised / exact reduced Newton tangent of the primal–dual system (safeguarded update). `KWCTAN=3` is part of the settings key: use it with a new `RUNTAG` |
| `-almc 0\|4` | 4 | Cosserat coupling: penalty / monolithic multiplier |
| `-asm 0\|1` | 1 | tangent assembly: FreeFEM forms / plugin on a fixed pattern |
| `-almlin schur\|mumps`, `-almpetsc`, `-almfall` | schur | MPI solve of the (U, λ) system and its PETSc options; MUMPS fallback options |
| `-slipexact 1` | 1 | slip rate law evaluated exactly, without the cap at x = 300 |
| `-localtol r` | 1e-10 (`LOCALTOL`) | after global convergence the local constitutive residuals must be below r; otherwise retry, then a clean stop |
| `-verbose 1` | (`VERBOSE=1`) | timing lines |
| `-asmcheck N` | (`ASMCHECK=N`, off) | every N-th Newton iteration of the run (the first included) the matrix is also built by the forms and compared entry by entry; stop above 1e-12 of the largest entry |
| `-lin direct`, `-nlogit 1`, `-lam0 v` | — | checks: serial direct solve, one row per Newton iteration in `<tag>_newton.csv`, start value of λ |

With `-kwctan 0 -almc 0 -asm 0` the v2 solver takes the same steps as the base solver.

## Tried and removed (14 November 2026)

| Removed | Why |
|---|---|
| ADMM / split Bregman for δ = 0 | never converged: residual stalls near 1e-5 of its start after hundreds of iterations, with or without warm start, residual balancing and Anderson acceleration |
| Kobayashi–Giga regularisation | 7.5 iterations per step against 5.7 for primal–dual at the same sharpness; fails at γ = 2e4 |
| lagged-diffusivity tangent, Picard start | only needed to start the Uzawa iteration; linear convergence |
| Uzawa multiplier updates (Gauss mean, centroid) | 21 iterations per step against 6 for the monolithic multiplier, same solution |
| one multiplier per Gauss point | locks |
| merit-weight option | no effect on the iteration count |
| larger augmentation μ_c = 2400, 7540 | more iterations (14.0 per loaded step at 2400 against 6.0 at 754); the constraint is exact at any μ_c > 0 |
| GAMG, ILU(1), ILU(2), subdomain LU for the (u, θ) block | not faster than ILU(0) (production mesh, 2 ranks) |
| η* = 0.02 and 0.1, η_φ = 0.01 | parameter changes of the trials; v2 keeps the previous values |

The numbers behind this table are in `exp_findings.md` and `almc4_review.md`.
